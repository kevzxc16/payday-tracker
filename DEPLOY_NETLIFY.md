# Payday Tracker — Free Demo Deployment

This version is prepared for a temporary/demo deployment using a Render Free web service behind Netlify. The existing Python application architecture is preserved.

## Architecture

Browser
  -> https://payday-tracker-kevzxc.netlify.app
  -> Netlify rewrite/proxy
  -> Render Free Python web service
  -> app/server.py
  -> router / middleware / routes / services
  -> SQLite at /tmp/payday.db
  -> background scheduler

## Important free-tier limitation

This demo does NOT use a persistent disk. The SQLite database is stored at `/tmp/payday.db` and can be reset when the free service is restarted, redeployed, or otherwise recycled. Do not use this deployment as the durable production database.

Render's Blueprint specification supports `plan: free` for web services. Free web services can spin down after inactivity, so the first request after a period of inactivity may take longer to respond.

## 1. Deploy the backend to Render

1. Push this project to the GitHub repository.
2. In Render, choose **New -> Blueprint**.
3. Connect the repository containing `render.yaml`.
4. Review the `payday-tracker-api` web service.
5. Make sure the instance type is **Free** and no persistent disk is listed.
6. Deploy the Blueprint.
7. Open the Render service and copy its exact `onrender.com` URL.
8. Confirm `https://<render-host>/healthz` returns `{"status":"ok"}`.

If Blueprint setup still asks for payment, create the service manually with **New -> Web Service**, select the GitHub repository, choose **Free**, and use the Dockerfile.

## 2. Environment variables

The included Blueprint sets:

- HOST=0.0.0.0
- PORT=10000
- DB_PATH=/tmp/payday.db
- BASE_URL=https://payday-tracker-kevzxc.netlify.app
- DEBUG=false
- SECRET_KEY=generated by Render

SMTP is intentionally blank initially, so email delivery is not configured.

## 3. Connect Netlify

1. Open the existing Netlify site `payday-tracker-kevzxc`.
2. In the repository's `netlify.toml`, replace the placeholder Render hostname with the exact Render service URL, preserving `/:splat`.
3. Redeploy the Netlify site.

The Netlify 200 rewrite keeps the visitor on the Netlify URL while proxying requests to the Python backend.

For a real production deployment, move the database to durable storage such as a managed database or a paid persistent disk. The free demo is intended to demonstrate the architecture and use case, not guarantee permanent user data.
