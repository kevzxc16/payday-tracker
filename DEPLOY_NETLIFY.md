# Payday Tracker — Netlify Deployment

This deployment keeps the existing Python application architecture intact.
Netlify is the public HTTPS/proxy layer; the Python server runs as a persistent
Render web service. The app uses SQLite and a background scheduler, so a
persistent disk is attached to the Render service.

## Architecture

Browser
  -> https://payday-tracker-kevzxc.netlify.app
  -> Netlify rewrite/proxy
  -> Render Python web service
  -> app/server.py
  -> router / middleware / routes / services
  -> SQLite at /data/payday.db
  -> background scheduler

## 1. Deploy the backend to Render

1. Put this project in a GitHub repository.
2. In Render, choose **New -> Blueprint**.
3. Connect the repository containing `render.yaml`.
4. Review the `payday-tracker-api` web service.
5. Deploy the Blueprint.
6. The Blueprint uses the Singapore region and a 1 GB persistent disk.
7. Open the Render service and copy its exact `onrender.com` URL.
8. Confirm `https://<render-host>/healthz` returns `{"status":"ok"}`.

The persistent disk is intentional: the application stores user data in SQLite.
Without a persistent disk, Render's filesystem is ephemeral and database changes
can be lost on deploy/restart.

## 2. Verify Render environment variables

Required values:

- HOST=0.0.0.0
- PORT=10000
- DB_PATH=/data/payday.db
- BASE_URL=https://payday-tracker-kevzxc.netlify.app
- DEBUG=false
- SECRET_KEY=<generated by Render>

SMTP is intentionally blank initially, so notifications use console mode.
Add real SMTP credentials later if email sending is needed.

## 3. Connect Netlify

1. Open the existing Netlify site `payday-tracker-kevzxc`.
2. Deploy this repository/folder as the site's source.
3. Netlify will use `netlify.toml`.
4. In `netlify.toml`, replace:

   `https://payday-tracker-api.onrender.com/:splat`

   with the exact Render service URL, preserving `/:splat`.
5. Redeploy the Netlify site.

The `200` rewrite keeps the visitor's address bar on the Netlify URL while
Netlify fetches the application from the external backend.

## 4. Test the complete use case

## 5. Email later

When you are ready for real email delivery, add SMTP values to the Render
service environment variables. Do not commit a real `.env` file or passwords.

## Important cost note

The included Render Blueprint uses a paid web-service plan because Render
persistent disks require a paid web service. This preserves SQLite data across
restarts/deploys. A free/ephemeral backend can be used for a temporary demo,
but database changes should not be treated as durable.
